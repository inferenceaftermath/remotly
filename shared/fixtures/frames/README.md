# Expected frames for the shared terminal fixtures

Generated by `bridge/scripts/gen-frames.ts` from the raw herdr reads in `../reads/`; do not edit by hand.
Every `../reads/<name>.ansi` (a `pane.read source=visible format=ansi strip_ansi=false` result, with
`<name>.json` metadata and `<name>.txt` herdr's own plain-text read of the same screen) has:

- `<name>.frame.json` — the `frame` message (`shared/protocol/remotly-protocol.md` §7) a client receives on watch start:
  `full: true`, a fresh per-connection style table (so `styles` lists every non-default style used, ids
  assigned in first-use order; id 0 is the implicit default), `pane` = fixture name, `rev` = 1, `cols`/`rows`
  from the fixture's `pty`. It contains exactly `rows` lines; rows herdr did not return (it trims trailing
  blank rows) are `{"y": n, "runs": []}`.
- `<name>.txt` — plain-text rendering of the same rows: gaps as spaces, trailing spaces trimmed, one line per
  parsed row (so fewer lines than `rows` when the screen ends in blank rows), trailing newline.

Client suites (iOS FlowKit, Android `:core`) should decode `<name>.frame.json`, paint it into a
`cols` × `rows` grid and check that the grid text equals `<name>.txt` (treating absent rows as blank), that
runs never extend past `cols`, and that a run with `w: 2` is a single wide grapheme. The bridge test
`bridge/test/terminal/fixtures.test.ts` asserts the current encoder reproduces these files (frame JSON compared structurally, `.txt` exactly),
so a change here is a protocol change. Regenerate: `cd bridge && node scripts/gen-frames.ts`.

Provenance: the reads were captured with `bridge/scripts/capture.ts` in a scratch directory and redacted (`user@host`,
`/home/user/…`, generic account labels). Captures made in the author's own sessions (`top`, the `pi-*` screens, the
`claude-working` / `claude-finished` transcripts) were removed before publication; re-capture in a throwaway account if
you need them, and keep anything personal out of this directory.
